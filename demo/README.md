# 独立演示版专区：仅用于演示

> **本文件夹及其全部子目录仅保存临时演示版内容。正式开发不得以此处的设计、代码、数据、接口、测试或演示结果作为参考、实现依据、验收依据或事实证据。**
>
> 演示版允许写死设备、资料、推荐和流程结果。这些简化不适用于正式产品；不得将本目录内容复制、导入或合并到正式模块。

本目录是一个可独立启动的本地演示服务：只用 Python 标准库，离线运行，数据写在 `demo/runtime/`。它演示原项目的完整流程（知识采集 → 推荐 → 手动采用 → 会话与采集 → 分析比较 → 反馈优化 → 历史与导出），但页面、数据与结果**全部是固定样例和模拟数据，不是真实实测**。

## 快速启动

在项目根目录 `E:\code\game` 执行：

```
py -3.13 -B demo/server.py --port 8765
```

或直接双击 `demo\start-demo.cmd`（会自动在 `py -3.13` → `py -3` → `python` 之间挑选可用解释器）。

启动成功后浏览器打开 <http://127.0.0.1:8765/>。窗口建议 1366×768 或 1920×1080。

修改 Python 代码后必须停止旧进程并重新启动服务，刷新网页不会重新加载 Python 模块。当前代码版本为 `demo/1.3`，健康接口包含 `ui_contract=conversation/2` 及 `device.check`、`intent.submit`、`log.capture_recent`、`feedback.review` 能力。新版页面发现旧服务时会明确提示重启，避免出现页面已更新但按钮调用失败的情况。

| 需求 | 做法 |
|---|---|
| 换端口 | `py -3.13 -B demo/server.py --port 8800`，或 `demo\start-demo.cmd --port 8800` |
| 换数据目录 | 加 `--data-dir <路径>`（默认 `demo/runtime/`） |
| 停止 | 在运行窗口按 `Ctrl+C` |
| 只能本机访问 | 服务只接受回环地址；`--host` 传其他地址会报错退出，不会对外监听 |
| Python 版本 | 需要 3.11+；本轮验证使用 3.13 |

启动失败时的退出码：`2` 参数非法，`3` 演示资源加载失败，`4` 端口被占用（不会结束已有进程，换 `--port` 即可）。

## 会看到什么

首次进入为通用对话页，没有预置游戏卡。主导航为“与助手对话”“我的游戏”“历史记录”；有游戏卡后，“更多功能”提供方案、测试、反馈、资料及设备背景入口。

“检查本机信息”位于对话输入框下方，点击后显示并保存固定的 i7-14650HX、RTX 4060 Laptop、16 GB 内存、8 GB 显存、621.01 驱动和 2560×1600 / 165 Hz 桌面信息。它按用户要求使用静态配置，不执行真实硬件探测。

当前只开放使命召唤：现代战争 I。先输入“我想玩使命召唤现代战争1”，再输入“我想要在保证流畅的前提下 尽可能保证画面的丰富感”。助手约 3 秒后回复，最后一次回复后整理约 1 分钟，15 份资料、14 项设置方案和游戏卡一起就绪；聊天内容单独滚动，输入区固定。之后按设备与背景、资料与依据、设置详情、游玩日志、体验反馈浏览。资料、推荐与帧时间数据均由本地固定内容提供。

设置按画质类别分组展示，统一“查看依据”包含来源观点、可选做法和取舍；没有生成或重新生成按钮，保留手动确认采用。游玩日志以“前一次 / 前两次 / 前三次”单选其中一份，文件上传收进高级选项。输入“爆炸时画面卡顿”后提交，显示约 30 秒重新分析提示，再给出单项调整建议；等待、刷新恢复与结果发布由本地服务端任务负责。

玩家页面不显示开发者演示工具与内部标识；开发文档、数据元信息和下载产物保留演示性质。旧地平线资源只作内部归档，不进入玩家流程。

## 数据与重置

- 所有运行数据在 `demo/runtime/`：`demo.sqlite3`、`uploads/`（上传副本与导出文件）、`shots/`（本轮验收截图）。
- 重置只清理登记过的演示对象与上传副本，不接受任意文件路径；删除整个 `demo/runtime/` 目录即可空白重来。
- 服务不会导入 `game_app`、`game_collector`，不读写正式数据库、密钥或 `runs/`；正式模块也不依赖本目录。
- 备份与恢复只包含当前案例的演示对象和受管理文件；导出首行写明“演示报告，非真实实测”。
- 页面里选中的摘要/推荐记在本机 `localStorage`；换浏览器后可先进入“我的游戏”恢复服务端卡片与结果进度。

## 与正式项目的关系

演示版用于展示原项目的功能流程。这里的功能通过固定样例与简单规则实现，**不能反向证明正式项目已经实现相应能力**。

- 正式需求及工程依据继续以根目录设计、`docs/technical-design/` 与正式源码为准。
- `game_app/`、`game_collector/`、正式测试、正式数据库及 `runs/` 不由演示版修改或消费。
- 演示版独立启动、独立保存状态，不配置真实模型密钥，不连接外网，不启动或控制游戏及采集工具。
- 用户指定真实设备与游戏，不代表演示服务已经读取它们；设备检查使用固定档案；本机检测与日志读取均为演示流程，不代表读取真实设备或游戏文件。
- 性能数字来自本地确定性帧时间样例，由演示代码真实计算指标，但**不是真实游戏帧率**；前后差异不构成因果结论，也不代表玩家一定满意。
