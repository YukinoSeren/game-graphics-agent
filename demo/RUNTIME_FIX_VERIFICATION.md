# 运行实例修复与验证记录

> 本目录仅用于临时演示。正式开发不得以这里的代码、数据或结果作为参考或验收依据。

日期：2026-11-03。

## 原因与修复

1. 8765 端口仍由早先启动的 Python 进程提供服务。它返回双游戏目录和旧导航，未加载新的设备检查与需求入口；网页静态文件已经更新，形成前后端不一致。已备份 `demo/runtime/demo.sqlite3`，停止确认过的旧服务进程，并以最新版重启。当前健康接口返回 `demo/1.1`、`conversation/1` 和新操作能力。没有清空旧演示数据库。
2. 补充信息操作生成的 `DeviceScan` 只有部分字段，对话页曾直接读取其中不存在的桌面分辨率，导致页面报错。现改为读取最近一次完整设备检查，只有部分记录时仍保留检查按钮。
3. 增加前后端能力检查：页面初始化先检查所需能力，旧后端会显示重启提示，不再静默显示无法工作的入口。
4. 在浏览器发现的方案条件文案、反馈调整设置名和结果标识已补充格式化，固定来源性质仍保存在原始记录与下载产物中。

## 实际验证

命令：

```text
py -3.13 -B -m unittest demo.tests.test_onboarding_runtime demo.tests.test_device demo.tests.test_information demo.tests.test_capture demo.tests.test_feedback demo.tests.test_sessions -q
```

实际结果：40 tests，OK，退出码 0。新增检查先复现缺失能力标识、设备字段不足导致的对话页异常，再在修复后通过。

浏览器操作使用隔离服务 `8766` 和 `demo/runtime/device-flow-audit/`：设备检查 → 需求提交 → 整理后建卡 → 生成 14 项方案 → 确认采用 → 固定帧数据测试 → 分析 → 反馈建议，均获得有效结果。分析产生 `usable` 摘要；反馈生成一项阴影调整。重新打开浏览器进入游戏库后，测试进度可恢复。执行补充信息操作后返回对话页，完整设备摘要与检查按钮仍可用。

主服务 `8765` 已实际点击设备检查，显示 RTX 4060 Laptop、16 GB 内存、165 Hz；展开详情后 CPU、显存、驱动、系统和桌面分辨率可见。主服务首页没有因验证而预先添加游戏卡。截图和浏览器运行记录存放于上述隔离运行目录。

所有外部能力继续使用固定内容，未执行硬件探测、联网调研、模型调用或真实游戏采集。测试数据位于演示目录；主工作区重启前备份位于 `demo/runtime/backups/`。
