# 02 公共知识、采集与更新设计

> 推荐设计 v1.0；复用现有采集契约，不重写冻结研究样本。  
> 返回：[总设计](../../project-design.md)；前置：[知识契约](../../knowledge-intake-contract.md)。

## 1. 本章解决的接口问题

已有工作明确了如何收集和保存资料，本章补充它怎样服务整套产品：何时复用、何时补查、怎样输出给推荐模块，以及更新后怎样影响已有玩家方案。

输入为 GameContext、DeviceSnapshot 及当前知识包版本；输出为 KnowledgePackage。包中包含可接受的原文记录、配置模板、设置目录、明确约束、资料缺口、采集范围和停止原因，不直接等于玩家推荐。

## 2. 公共知识与个人经验隔离

- 公共知识：官方说明、公开推荐、测试、技术支持条件、版本变化。
- 私人经验：某设备某会话的实际配置、运行结果、偏好与反馈。
- 同一玩家的多次测试可以影响其下一轮推荐，不能因为一次改善就升级成所有显卡通用规律。
- 本机经验若以后转为公共资料，必须另建脱敏、授权、条件与复核流程；首版不做此功能。

## 3. 复用与更新

每次请求先查本地包的游戏身份、平台、适用版本、来源获取时间、重要未解决项和历史证据覆盖。查询先字段过滤，再按实际需要检索正文；首版不依赖向量数据库。

| 状况 | 动作 |
|---|---|
| 有近期复核过的匹配包，无已知关键变化 | 复用，并展示最近检查时间 |
| 有内容但缺同卡/关键设置 | 复用已有资料，只针对差异补查 |
| 已知游戏更新影响设置 | 定向复查受影响设置和方案 |
| 版本未知且资料较旧 | 检查官方更新，再决定分支是否保留 |
| 新游戏或本地无可用资料 | 完整来源发现与提取 |

建议非游戏运行期间，对初次进入的游戏和玩家主动刷新时执行更新检查；“7 天后检查来源”等时间策略仅为可配置调试值，不能把“年龄小于7天”等同于兼容当前版本。

## 4. 覆盖目标与预算

建立覆盖矩阵，维度至少为：显示/图形菜单、硬件档位、分辨率、超分/帧生成/光追分支、推荐取舍、实测环境、版本与技术约束。

覆盖状态分为 `covered`、`partially_covered`、`unknown`、`not_applicable`，每格有依据。不能用设置条数或搜索网页数量单独宣布充分。

为课程项目设置两种运行配置：

| 配置 | 推荐用途 | 建议初值，不是质量保证 |
|---|---|---|
| smoke | 开发验证接口与预算 | 1—3 URL、0—1补查轮、1—3模型调用 |
| thorough | 玩家首次深入收集 | 先沿用12 URL、12搜索、2补查轮、16模型调用；覆盖不足时允许从检查点继续新增预算 |

用户选择充分优先，产品正常入口使用 thorough。达到预算时保存成果和缺口，不为了完结而降校验；增补预算是显式的下一任务，复用旧内容而不是重新抓所有来源。费用没有实际计量就只展示调用/token，不估金额。

## 5. 来源角色与独立性

官方适合核实功能、约束、版本；实测适合条件化性能；作者配置适合作为基准；论坛适合症状与问题线索。不同角色不采用固定“官方权重10、论坛权重1”的统一分数。

作者、测试、转载链、修订关系尽量关联；独立性未知就记录未知。相同原文换域名不能增加独立支持。

推荐模块接收到的不仅有结论，还要有 author_claim、measured_result、observation、agent_inference 等性质与来源作用范围。

## 6. 设置目录与别名

- 同一游戏中显示设置、图形设置及影响体验的相关设置分组保存。
- 保留菜单原名与原始值，规范中文名仅作为展示别名。
- 音频、FOV 等与渲染优化关系不同的项目保留目录位置，但分类为 audio/camera/other；不因在性能菜单内就当成 GPU 负载优化项。
- 跨来源别名映射需要原文或人工/模型复核依据；不能仅凭“听起来相近”合并。
- 可选值未被资料覆盖时，目录显示“已证实取值集合”，不宣称全部枚举。

## 7. 图片与缺口

当前实现只登记图片线索。推荐的增强流程是：仅对影响决策的菜单截图/图表定向读取，保存图片定位、提取方法、表头/单位和复核结果。OCR/VLM 结果和原生文本一样经过入库检查。

数字看不清、图例不明、配置标签修订未落实时保持未解决；不把内容要求转嫁为玩家必须逐页截图。长视频继续暂缓。

## 8. 从采集到推荐的门槛

`accepted` 只代表本条知识符合入库规则；推荐引擎还要检查当前玩家的硬件/版本/取值与组合。`quarantined` 原文仍可供修复定位，但不能作为推荐事实输入。

KnowledgePackage 必须携带：

1. game_id、package_version、source_revision_ids、created_at。
2. setting_catalog、configuration_templates、measurement_evidence、constraints。
3. coverage_matrix、critical_gaps、noncritical_gaps、stop_reason。
4. 已执行的检查和未覆盖的检查。
5. 转载、冲突、版本影响关系。

## 9. 更新传播

新资料进入后建立新的知识包版本。对依赖受影响证据的推荐标记 `needs_review`，记录具体设置、旧证据、新变化和影响理由，不直接改玩家配置。

适配平台不一致或版本关系不明时只提出复核；版本变化不自动等于旧推荐错误。保持个人历史可用以复现旧会话。

## 10. 对已有代码的增量建议

保留现有 sources/records 与输出文件。后续优先补：知识包索引、来源跨运行复用、带来源的别名表、覆盖矩阵和已验证范围明确的图像能力。复杂时间推理与全文/向量方案按真实查询瓶颈再增加。

这些均是后续工程建议，本轮不更改采集器、运行输出或冻结样本。
