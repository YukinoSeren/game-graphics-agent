## 三、重点审计

### 1. D-P01：首次选游戏

空产品库能否只输入游戏名，逐步取得合法游戏、上下文和安装引用？

检查provisional身份、未知平台、同名歧义、用户作用域、并发声明槽，以及身份核验后输出新上下文的规则。

不得靠预置夹具ID、默认平台或隐式外部调用绕过缺口。

### 2. D-P02：本机设置登记

无公共知识和配置适配器时，能否登记条目并保存独立基线？

检查当前精确键、版本头、目录更正、恢复旧名称、并发后继及跨安装引用。

重点检查是否可能形成环、误合并不同设置、自动迁移值或改变历史配置。

### 3. D-P03：测试协议

检查指标目录、规则版本、首次定义登记、TestProtocol创建与版本关系。

确认TestProtocol和ComparisonProtocol的引用、职责及冻结时序不混淆。

检查空目录、坏key、条件类型、帧流、未知值、并发和旧协议兼容。

### 4. D-P04：已处理问题更正

检查resolved/skipped问题能否通过正式入口创建关联的新请求。

重点核对facts_only的创建、回答、部分回答、跳过、过时修订、历史引用不可用及取消竞态。

无论源任务running还是终态，均不得修改其TaskRun、TaskEvent、TaskInputRevision、成果或触发重跑。

### 5. 全局一致性

- DTO定义、路由、页面动作、返回资源和后继调用能否完整衔接。
- 来源、权限、不可变历史、文件发布、事务和幂等是否一致。
- product-contract/0.3与旧0.1/0.2对象、请求哈希和原响应是否兼容。
- 34个实施任务是否完整、依赖无环，且不存在隐藏的实现或验收循环。
- 核实原55个模块验收是否全部保留，新增后是否确为63个；核实基础验收和计划覆盖。
- 检查本地链接、锚点、表格、JSON示例及请求字段一致性。

## 四、审计标准与输出

优先找会导致错误实现的真实缺陷，不为凑数量提出问题。

区分：

- 契约冲突或操作入口缺失
- 实施计划缺陷
- 已明确登记的待确认决策
- 已明确登记的外部验证门禁
- 可选改进

每个实质问题给出：

- 优先级及受影响范围
- 文件路径和准确行号；冲突时列出两端
- 一个具体失败场景
- 当前哪条定义不足以阻止该失败
- 最小修订建议
- 需要补充或调整的验收场景

不要把已有降级规则能够覆盖的情况重复报成缺陷；如果认为覆盖不足，指出具体缺口。
